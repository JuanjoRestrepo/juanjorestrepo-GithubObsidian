# Benefits of Breaking Data into Tables
---
- Efficient **storage**
- Easier **manipulation**
- Greater **scalability**
- Logically **models** a process
- Tables are **related** through **common values (keys)**

# Joins
---
- Associate correct records from each table on the fly.
- Allows **data retrieval** from multiple tables **in one query**
- Joins are not physical - they persist for the duration of the query execution


# 1. Cartesian (Cross) Joins
---
- They allow you to take each record from the first table and match it with all of the records from the second table.
- **CROSS JOINs**: each row from the first table joins with all the rows of another table.
- Not frequently used
- Computationally taxing
- Will return products with the incorrect vendor or no vendor at all

![[Pasted image 20230927160537.png|500]]

A Cartesian Join allows you to take each record from the first table and match it with all of the rows from the second table; therefore, If the first table contains x rows and the second table contains y rows, you'll have the end result of x multiplied by y.

### How do we write this out?
---
```SQL
SELECT product_name
,unit_price
,company_name
FROM suppliers CROSS JOIN products;
```
![[Pasted image 20230927161052.png]]


Output will be the **number of joins in the** ***First table*** **multiplied** by the **number of rows in the** ***Second table***


# 2. Inner Joins
---
- The Inner Joins are one of the most used Joins in SQL.
- The **INNER JOIN** keyword selects records that have **matching values in both tables**

![[Pasted image 20230927161511.png]]

We have table 1 and table 2, and what it is going to return is **only the records that are matching in both.**

It's going to **look for that key, in that link**, and even if there's more records in table 1, it's not going to bring those back. I**t's just going to bring back the matches**

- In other words, **This is where keys become very important in table**s. We have table 1 and table 2 and what it is going to return is **only the records that are matching in both.**

## Inner Join Example
---
```SQL
SELECT suppliers, CompanyName
,ProductName
,UnitPrice
FROM Suppliers INNER JOIN Products ON Suppliers.supplierid = Products.supplierid
```

### Inner Join Syntax
---
- Join type is specified (**INNER JOIN**)
- Join condition is in the **FROM** clause and uses the **ON** clause
- Joining more tables together affects overall database performance
- You can join multiple tables, no limit
- List all the tables, then define condtions

### Example with Multiple Tables

![[Pasted image 20230927162326.png|400]]

```SQL
SELECT o.OrderID, c.CompanyName, e.LastName
FROM ((Orders o INNER JOIN Customers c ON o.CustomerID = c.CustomerID)
INNER JOIN Employees e ON o.EmployeeID = e.EmployeeID);
```

# 3. Aliases and Self Joins
---
## What is an Alias?
---
- SQL aliases give a table or a column a temporary name
- Make column names more readable
- An alias only exists for the duration of the query

```SQL
SELECT column_name
FROM table_name AS alias_name
```

### Query Example Using Alias
```SQL
SELECT vendor_name
,product_name
,product_proce
FROM Vendors, Products
WHERE Vendors.vendor_id = Products.vendor_id;
```

#### Using Alias
```SQL
SELECT vendor_name
,product_name
,product_proce
FROM Vendors AS v, Products AS p
WHERE v.vendor_id = p.vendor_id;
```


## Self Joins
---
- Match customers from the same city.
- Take the table and treat it like two separate tables
- Join the original table to itself
```SQL
SELECT column_name(s)
FROM table T1, table T2
WHERE condition;
```

### Self Join Example
```SQL
SELECT A.CustomerName AS CustomerName1,
B.CustomerName AS CustomerName2, A.City
FROM Customers A, Customers B
WHERE A.CustomerID = B.CustomerID AND A.City = B.City
ORDER BY A.City;
```
