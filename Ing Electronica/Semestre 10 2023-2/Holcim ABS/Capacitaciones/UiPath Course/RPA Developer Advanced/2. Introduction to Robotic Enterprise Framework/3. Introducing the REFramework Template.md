
# ¿Qué es el REFramework?

En términos generales, un marco es una plantilla que lo ayuda a diseñar (automatizar) procesos.

Robotic Enterprise Framework (REFramework) es una plantilla de UiPath Studio creada con máquinas de estado. Actúa como punto de partida para proyectos de RPA listos para producción, especialmente los que requieren un procesamiento escalable. Fue creado para adaptarse a todas las mejores prácticas relacionadas con el registro, el manejo de excepciones, la inicialización de aplicaciones y estar listo para abordar cualquier escenario empresarial.

La plantilla contiene varios contenedores de estado prediseñados para inicializar aplicaciones, recuperar datos de entrada, procesar los datos y finalizar la transacción. Todos estos estados están conectados a través de múltiples transiciones que cubren casi todas las necesidades en un escenario de automatización estándar.

# ¿Por qué usar REFramework?

Hay un par de problemas que podemos enfrentar cuando ejecutamos proyectos de automatización en producción. Afortunadamente, todos ellos pueden abordarse utilizando la plantilla REFramework.

### El robot se detiene ante el primer error inesperado.
____________________________________
REFramework tiene un mecanismo de manejo de excepciones incorporado para detectar todas las excepciones inesperadas e intentar continuar con la ejecución del proceso.
![[Pasted image 20230728090159.png|300]]

### Un bloqueo de la aplicación detiene la automatización.
____________________________________
Por lo general, cuando una aplicación deja de responder, los humanos la reiniciamos y continuamos con nuestro trabajo. REFramework hace algo similar, tiene un mecanismo de reintento incorporado para recuperarse de excepciones de aplicaciones inesperadas. Todas las aplicaciones utilizadas en el proceso se cierran, luego el proceso vuelve al estado de Inicialización y vuelve a intentar la transacción actual.

Cuando se usa una cola de Orchestrator para datos de entrada, se debe usar la función Reintentar de la cola, en lugar del mecanismo de reintento de REFramework.

![[Pasted image 20230728090250.png|400]]

### Los datos de transacción no válidos dejan de procesar todas las demás transacciones.
____________________________________
REFramework utiliza un tipo de excepción especial, BusinessRuleException, para el caso en que los datos de entrada no sean válidos. En este caso, la transacción se marca como 'fallida' y la ejecución continúa con la siguiente transacción.

Es responsabilidad del desarrollador de RPA implementar la lógica para generar BusinessRuleExceptions cuando los datos de entrada no son válidos.

![[Pasted image 20230728090529.png|400]]

### Los valores codificados y/o dispersos para rutas de archivos, correos electrónicos y credenciales tienen un impacto negativo en la seguridad y el mantenimiento.
____________________________________
REFramework tiene un archivo de configuración centralizado y también utiliza activos en Orchestrator para una administración más sencilla del valor de configuración después de la implementación.

![[Pasted image 20230728090625.png|500]]

### Difficult to troubleshoot an error in production.
____________________________________
Para ayudar con el mantenimiento de los proyectos de automatización, REFramework tiene un mecanismo de registro y las capturas de pantalla se toman automáticamente cuando ocurre un error inesperado.

### Los grandes proyectos de automatización son difíciles de mantener.
____________________________________
La plantilla REFramework se construye utilizando una máquina de estado con diferentes estados y flujos de trabajo para cada etapa del proceso (inicio del proceso, obtención de datos, procesamiento de datos, finalización del proceso). De esta manera, es más fácil organizar los flujos de trabajo en el proyecto.

## **The REFramework architecture**
____________________________________
![[Pasted image 20230728091050.png]]

1. **Initialization:** This is where the process starts. It is a state where the process reads the settings and initializes applications in order to make sure all the prerequisites for continuing the execution are in place
2. **Get Transaction Data:** After a successful intialization, this state gets the next transaction item. This can be a queue item or any item of a collection (datarow, email, string). By default, transaction items are of queue item type. However this can be easily changed to suit the needs of any type of process.
3. **Process Transaction:** After a transaction item has been retrieved, this state performs actions in various applications using the information held in the transaction item. This is also the state in which processing exception handling is performed, queue item statuses are set and the retry mechanism is triggered.
4. **End Process:** This state is executed when the applications must be closed and the process terminated either because of a system exception in the initialization state or because there are no more transaction items to process.

### Para tener una mejor comprensión de cómo podemos usar REFramework, ¡veamos un escenario práctico!

Hay una lista de personas y sus direcciones de correo electrónico en una hoja de cálculo. Se debe enviar un correo electrónico a cada uno de ellos con un mensaje personalizado basado en una plantilla.

![[Pasted image 20230728093049.png]]

1. **Initialization State:** Read data from a spreadsheet and read the email template from a text file.
2. **Get Transaction State:** Retrieve one row from the spreadsheet, which contains the name and the email of one person.
3. **End Process State:** After all rows are processed, finalize the execution. Since emails can be sent directly by the robot, there is no need to close any email applications.


### Por último, la plantilla REFramework ofrece dos formas de implementación:

#### With Queues: 
The first way focuses on building a project using the REFramework with Orchestrator Queues.

#### WITHOUT QUEUES

- REFramework es la **plantilla más utilizada al desarrollar escenarios comerciales complejos**.
- Es más fácil adaptar un proceso comercial a la plantilla en lugar de crear todos los mecanismos necesarios para la automatización lista para la producción desde cero.
