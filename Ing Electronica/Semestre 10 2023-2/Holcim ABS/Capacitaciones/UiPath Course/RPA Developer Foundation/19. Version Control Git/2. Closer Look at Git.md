
## Descripción general de Git
_________________________________________________________
Git es un sistema de control de versiones de código abierto. Git se distribuye, a diferencia de los sistemas de control de versiones centralizados más antiguos, como SVN y CVS, lo que permite a cada desarrollador tener un historial completo de su repositorio de código localmente. Esto hace que la clonación inicial del repositorio sea más lenta, pero las operaciones posteriores, como confirmar, culpar, diferenciar, fusionar y registrar, son mucho más rápidas.

Git también tiene un buen soporte para bifurcar, fusionar y reescribir el historial del repositorio. La solicitud de extracción es una característica popular que permite a los equipos colaborar en ramas de Git y revisar de manera eficiente el código de los demás. Git es el sistema de control de versiones más utilizado en el mundo y se considera el estándar moderno en el desarrollo de software.

## **How Git works?**
_________________________________________________________
Here is a basic overview of how Git works:

1. Create a **repository** (project) with a Git hosting tool.
2. **Copy or clone** the repository to your local machine.
3. Add a file to your local repository and **commit** (save) the changes locally. 
4. **Push** your changes to the remote repository.
5. **Pull** the file to local repository and make changes, and then **commit** and **push** the file.
6. Create a **branch** (alternative), make a change, commit the change.
7. Open a **pull request** (propose changes to the master branch).
8. **Merge** your branch to the master branch.


## **SVN and Git side-by-side**
_________________________________________________________
#### SVN
Con un sistema centralizado, el sistema de control de versiones SVN almacena todos los archivos y datos históricos en un servidor central. Los desarrolladores envían sus cambios a este repositorio del servidor central.

**Trunk:** El **Trunk/Troncal** es el centro de su código y producto actuales y estables. Solo incluye código probado e ininterrumpido.

**Branches/Ramas**: Aquí se agregan los nuevos códigos y características. Utilizando una copia del código troncal, los miembros del equipo realizan investigación y desarrollo en la sucursal. Esto permite que cada miembro del equipo trabaje en las funciones mejoradas sin interrumpir el progreso de los demás.

**Tags**: las etiquetas son un duplicado de una rama en un momento determinado. Las etiquetas no se usan durante el desarrollo, pero se usan durante la implementación una vez que se completa el código de la sucursal. Marcar el código con etiquetas facilita la revisión y, si es necesario, la reversión del código.

#### Git
Git utiliza un repositorio central y una serie de repositorios locales. Los repositorios locales son copias exactas del repositorio central que contienen su historial completo de actualizaciones.

El flujo de trabajo de Git es similar a SVN, pero con un paso adicional. Para crear una nueva característica, necesitamos tomar una copia exacta del repositorio central para crear nuestro repositorio local en su máquina local (considere esto como nuestro "troncal local").

Luego, trabajamos en nuestro repositorio local exactamente como lo haríamos en SVN creando nuevas ramas, etiquetas, etc. Cuando terminamos, fusionamos nuestras ramas en nuestro repositorio local (es decir, troncal local). Cuando estemos listos para fusionarnos con el repositorio central, empujamos nuestros cambios desde nuestro repositorio local al repositorio central.

Algunos de los beneficios incluyen lo siguiente:

- Es más rápido de cometer.
- No más punto único de falla.
- Está disponible sin conexión.
