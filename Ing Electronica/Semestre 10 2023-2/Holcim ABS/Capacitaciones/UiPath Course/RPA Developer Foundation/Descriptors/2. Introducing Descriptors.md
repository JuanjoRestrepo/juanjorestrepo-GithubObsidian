
# ¿Qué es un Target?
_______________________________________________________________
- Un Target es un elemento de la interfaz de usuario con el que desea interactuar para realizar algunas acciones en él.
- Por ejemplo, un botón para hacer clic, un cuadro de texto para escribir. Aquí, el botón y el cuadro de texto son el objetivo.
- Los elementos de la interfaz de usuario se refieren a todas las piezas de la interfaz gráfica de usuario que construyen una aplicación.
- Los elementos de la interfaz de usuario pueden ser ventanas, casillas de verificación, campos de texto o listas desplegables, etc.

# ¿Cómo identifica un robot el objetivo correcto?
_______________________________________________________________
Los métodos de orientación ayudan a identificar el elemento de destino correcto. Las actividades modernas de automatización de la interfaz de usuario utilizan varios métodos de orientación para identificar el elemento de la interfaz de usuario con el que desea que interactúe el proceso.

Los métodos de segmentación clave son:

1. **Selectors:** A selector is a feature that enables the identification of the User Interface elements through its address and attributes stored as XML fragments. If we think of GUI interfaces as a complex hierarchy of containers going from the top node to the specific UI element, the selector XML code acts as an address for the element. 
	- Selectors requiere an exact match

2. **Fuzzy Selectors:** enable you locate strings based on a pattern, rather than on an exact match to your input. This results in a more flexible method of identifying elements and validates selectors according to multiple attributes, even if some are prone to change during the automation process.
3. **Image:** reads the array of pixels in a visible region of the application window to identify if it maches the target array.  
4. **Native Text:** This method is best suited to automating legacy applications that don't have correctly defined UI elements.
	1. Native Text is used to detect the position of the text on the screen to perform the required action.
	2. When enabled, other targeting methods won't apply to that particular UI element

Los elementos de destino pueden tener atributos, ubicaciones de pantalla o imágenes cambiantes. Para aumentar la precisión utilizamos Anchors.

Los Anchors nos ayudan a identificar los elementos inestables con los que necesitamos trabajar en relación con los elementos más estables.

# ¿Qué es un Anchor y cuándo debo usarlo?
_______________________________________________________________
Un Anchors es otro elemento de la interfaz de usuario que ayuda a identificar de forma única el objetivo.

- Cuando indica un objetivo mediante una actividad de automatización de la interfaz de usuario moderna, UiPath intenta identificar y seleccionar automáticamente un ancla.
- También puede agregar manualmente hasta tres anclas al objetivo requerido.

![[Pasted image 20230721144315.png|200]]


Por ejemplo, en la imagen dada, el robot identifica el campo de Entrada (Objetivo) resaltado en verde al referirse a la etiqueta de Nombre (Anclaje) resaltada en azul.
![[Pasted image 20230721144350.png]]

En los casos en que se indiquen conflictos potenciales en la ventana de selección, puede aumentar la confiabilidad agregando múltiples anclas.

Por ejemplo, ingresando el valor en el campo de entrada On Us Check.

Solo un ancla a la etiqueta de un campo de entrada On Us Check no es confiable en el 100% de los casos. Todavía hay margen de mejora. Esto se debe a que la aplicación Double UI tiene la misma imagen para cada campo de entrada y etiquetas muy similares On Us Check y Not On Us Check.

![[Pasted image 20230721144451.png]]

En este caso, agregar (Cash In) que está cerca del elemento Target (On Us Check) como otro ancla hace que Target sea más confiable.

## **Nota**
Las actividades de diseño moderno utilizan un método UnifiedTarget para identificar los elementos de la interfaz de usuario en la pantalla.


# ¿Qué es el Unified Target/Objetivo Unificado?
_______________________________________________________________
Unified Target es el **frameworks/marco moderno** para la automatización de la interfaz de usuario.

Existen muchas tecnologías o métodos que facilitan las interacciones de la interfaz de usuario, como selectores, selectores difusos, imágenes, textos, visión por computadora, etc. Al usar un **framework/marco unificado**, todos los métodos se respaldan entre sí para una mayor confiabilidad y, de esta manera, puede asegurarse de que su robot superará cualquier obstáculo causado por puntos débiles al seleccionar el elemento de la interfaz de usuario.

Además, otra ventaja de usar un solo marco para un conjunto similar de actividades es que puede usarlo en todos sus flujos de trabajo como una solución lista para usar. Por lo tanto, no necesita perder tiempo configurando y considerando las particularidades de cada método utilizado, ya que es fácil de usar ejecutándose en segundo plano.

El objetivo unificado utiliza un par de frameworks para identificar elementos de la interfaz de usuario.

## UI Frameworks

De forma predeterminada, se utiliza un marco propietario para acceder a la ventana de la aplicación de destino; sin embargo, si no se detecta un destino, Studio ofrece dos alternativas:

- **AA (Active Accessibility/ accesibilidad activa):** para aplicaciones más antiguas.
- **UIA (Microsoft UI Automation):** para aplicaciones más nuevas.

Después de seleccionar un destino, la opción para cambiar el marco de la interfaz de usuario ya no está disponible.

![[Pasted image 20230721145353.png]]

- Un **objetivo unificado** (**Unified Target**) se compone de al menos un objetivo, con anclas opcionales. Básicamente, uno o más elementos de la interfaz de usuario.

- Cada elemento de la interfaz de usuario (**UI**) se encuentra utilizando una pila de métodos de orientación: Selectores, FuzzySelectors, Imágenes.

- Estos tres métodos de orientación son redundantes entre sí. Lo que significa que todos intentan identificar el elemento objetivo simultáneamente, y cualquiera que encuentre el objetivo primero, se considerará ese método de orientación.

La configuración del proyecto determina qué métodos de focalización usar en la detección de objetivos.

# ¿Qué son los Descriptores?
_______________________________________________________________
Ahora lo sabemos, la pantalla de selección le permite seleccionar, configurar, eliminar y administrar objetivos y anclas para cualquier actividad de la interfaz de usuario. Tales como: ***hacer clic, escribir, pasar el cursor, etc.***

El proceso oculto de encontrar un elemento de la interfaz de usuario utiliza los tres métodos de orientación disponibles: Selector, Selector difuso e Imagen.

El robot intenta encontrar un elemento de la interfaz de usuario (ya sea un objetivo o un ancla). Realiza búsquedas con los tres métodos de segmentación en paralelo.
El método que encuentre primero el elemento de la interfaz de usuario será el que se utilice para identificar el objetivo o ancla correspondiente.
Nota: el proceso de focalización ocurre nuevamente en tiempo de ejecución, con los tres métodos buscando en paralelo el objetivo. El método de segmentación que parece ser el más rápido en el momento del diseño puede cambiar en el momento de la ejecución.

Un elemento ancla/anchor y un elemento objetivo, cuando se identifican mediante sus respectivos métodos de orientación, forman un par único.

## **Scenario**
- Pensemos en un tipo de actividad.
- Hemos indicado el elemento de la interfaz de usuario para ingresar los datos en el campo de entrada Cash In.
- Además, agregamos un ancla a la etiqueta 'Cash In'.

## Durante el tiempo de ejecución
- Sabemos, en tiempo de ejecución, que los métodos de focalización funcionan en redundancia.
- El robot intenta con tres métodos de orientación (selector, selector borroso e imagen) para identificar el objetivo (campo de entrada de efectivo).
- Del mismo modo, trata de identificar el Ancla (etiqueta Cash In).
- Tres métodos de orientación para identificar un objetivo X Tres métodos de orientación para identificar el ancla (3X3).

Aquí, el robot genera nueve combinaciones 'Objetivo - Anclaje' debajo del capó.

![[Pasted image 20230721153634.png|350]]

El robot ejecuta todas estas nueve combinaciones posibles, en paralelo.

Cuando se encuentra un PAR ancla-objetivo, con cualquier método para cada uno, se ejecuta el tipo en Actividad.

**Nota:** El número de combinaciones depende del número de anclas. Un objetivo puede tener un máximo de tres anclas.
