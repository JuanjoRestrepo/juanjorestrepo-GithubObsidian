# ¿Qué son las variables?
Las variables son contenedores que pueden contener múltiples entradas de datos (valores) del mismo tipo de datos.
El valor de una variable puede cambiar a través de una entrada externa, la manipulación de datos o el paso de una actividad a otra.

# ¿Por qué son importantes?
Las variables nos ayudan a pasar datos de una actividad a otra. Avanzar en cualquier proceso de automatización sería difícilmente posible sin el uso de variables.
En Studio, las variables se utilizan para almacenar varios tipos de datos. Estos datos pueden ser un número entero, un booleano, una cadena y muchos más tipos de datos.

**Las variables se configuran a través de sus propiedades**. 
- Pueden configurarse en el panel Variables. El panel Variables le permite crear variables y realizar cambios en ellas.

Exploremos las propiedades principales en UiPath:

- **Nombre:** Debe ser lo más descriptivo posible para que su automatización sea fácil de leer para otros desarrolladores y para ahorrar tiempo. Este es un campo obligatorio. Si no agrega un nombre a una variable, se genera uno automáticamente.
	- Se recomienda usar PascalCase para nombres de variables (Por ejemplo: ItemValue, LastName.)
- **Tipo de variable:** Define qué tipo de datos se almacenan en la variable. En UiPath, el tipo de datos se declara cuando se crea la variable. El campo desplegable brinda acceso rápido a los tipos de datos más utilizados (vistos a continuación), pero hay muchas más opciones disponibles
	1. Boolean
	2. Int32
	3. String
	4. Object
	5. System.Data.DataTable 
	6. Array of [T]
	7. Browse for Types
- **Scope:** es un campo obligatorio y es la parte del flujo de trabajo en la que se llama a la variable por su nombre. El alcance de una variable se define por el nombre del flujo de trabajo en el proyecto de automatización. Una vez que se define el alcance, la variable se puede usar en ese flujo de trabajo y en todos los flujos de trabajo de sus hijos. 
	En UiPath, el alcance de una variable no puede exceder el flujo de trabajo en el que se definió. Dado que los proyectos de automatización empresarial rara vez consisten en flujos de trabajo únicos, necesitamos un tipo diferente de vehículo para pasar datos entre flujos de trabajo, y esto se denomina argumento.

- **Default:** En general, las variables tienen valores iniciales que cambian a lo largo del proceso. Para la mayoría de las variables, si no se asigna un valor inicial cuando se declara la variable, existe una regla predeterminada que asigna un valor.

# Tipos de Datos

Los tipos de datos describen qué tipo de datos puede contener una variable.
Por ejemplo, si el tipo de datos es Int32, la variable debe contener un número entero. Del mismo modo, si el tipo de datos es una cadena, la variable debe contener un texto.

### **¿Por qué son importantes?**
Las variables y los argumentos en Studio deben tener definido un tipo de datos específico. Esto asegura que se aplique el formato de datos correcto en cada etapa de un proceso automatizado. 

Los tipos de datos base son tipos de datos básicos, como números enteros, cadenas, fechas, etc. Incluyen todos los tipos que forman parte de cualquier lenguaje de programación .NET.
- Se utilizan como valores de variables.
- Se utilizan como valores constantes.
- Los procesadores pueden reconocerlos fácilmente.

1. **String:** System.String: utilizado para almacenar texto
2. **Numeric (Category):** Se utiliza para almacenar números. Existen diferentes subtipos de variables numéricas. Para algunos ejemplos:
	- Int32 - System.Int32 (enteros con signo): 10, 299, -100
	- Long - System.Int64 (enteros largos): 54354353430, -11332424D
	- Double - System.Double (permite decimales, precisión de 15-16 dígitos): 19.1234567891011
3. **Boolean:** System.Boolean: se utiliza para almacenar uno de dos valores: True or False.

4. **Collection (Category):** Esta categoría reúne todas las colecciones de objetos. Las colecciones se utilizan en gran medida para manejar y procesar datos complejos. Algunas de las colecciones más encontradas son:

# More on GenericValue

Al desarrollar un proceso de automatización, hay situaciones en las que no está seguro de qué tipo de datos se recuperan. Para averiguarlo, debe realizar algunas pruebas utilizando una variable con un espectro lo suficientemente amplio que pueda captar cualquier tipo de entrada.

Aquí es donde recomendamos usar temporalmente GenericValue Variables.

### ¿Qué es GenericValue?
El tipo de datos GenericValue (UiPath.Core.GenericValue) es particular de UiPath y puede almacenar cualquier tipo de datos, incluidos texto, números, fechas y matrices.

UiPath Studio tiene un mecanismo de conversión automática de variables y argumentos GenericValue, que puede guiar hacia el resultado deseado definiendo cuidadosamente sus expresiones.
Tenga en cuenta que el primer elemento de su expresión se utiliza como guía para la operación que realiza Studio.

Por ejemplo, cuando intenta agregar dos variables GenericValue, si la primera de la expresión se define como una cadena, el resultado es la concatenación de las dos.

Si se define como un Entero, el resultado es su suma.

### ¿Cuáles son algunos escenarios comerciales en los que utilizará GenericValue?
Los datos se extraen de un campo de la interfaz de usuario y se reenvían a otro flujo de trabajo sin procesamiento.
Dos versiones del mismo archivo de Excel se comparan columna por columna. Las columnas son diferentes en cuanto al tipo de datos, lo único relevante es qué entradas han cambiado.


## Métodos de conversión de tipos de datos

Estas son formas de cambiar una expresión de un tipo de datos a otro. Por ejemplo, la conversión de un número entero a una cadena o viceversa.

Aquí hay una lista de algunos de los métodos de conversión comúnmente usados para tipos de datos:

1. **Convert.ToString:**  Este método convierte el valor especificado en su representación de cadena equivalente. 
	- Puede ser Int32 a String.
	- ToString(Int32, Int32): convierte el valor de un entero de 32 bits con signo en su representación de cadena equivalente en una base especificada.
	- Por ejemplo: StrVar = Convert.Tostring(IntVar)
2. **Convert.ToInt32:** Este método convierte un valor especificado en un entero de 32 bits con signo. 
	- ToInt32(String): convierte la representación de cadena especificada de un número en un entero equivalente de 32 bits con signo. Hay otro método para convertir una cadena en un número entero: CInt (String)
	- ToInt32(Double): convierte el valor del número de punto flotante de precisión doble especificado en un entero equivalente de 32 bits con signo.
	- Ejemplo:
		- IntVar = ToInt32(StrVar)
		- IntVar = CInt(StrVar)
		- IntVar = ToInt32(DblVar)

3. **Double.ToString:** Este método convierte el valor numérico de esta instancia en su representación de cadena equivalente. 
	- Por ejemplo: StrVar = DblVar.ToString: este método muestra las representaciones de cadena de varios valores Double.
4. **Double.Parse:** Este método convierte la representación de cadena de un número en su equivalente numérico de punto flotante de doble precisión.
	- Por ejemplo: DblVar = Parse(StrVar) 
5. BooleanToString: Este método convierte el valor de esta instancia en su representación de cadena equivalente (ya sea "True" o "False").
	- Por ejemplo: ToString()
1. Convert.ToBoolean: Este método convierte un valor especificado en un valor booleano equivalente.
	- Por ejemplo:ToBoolean(Int32): convierte el valor del entero de 32 bits con signo especificado en un valor booleano equivalente.
1. Convert Date to String:
- DateTime.Now Property: obtiene un objeto DateTime que se establece en la fecha y la hora actuales en este equipo, expresadas como la hora local.
- ToString(DateTime): convierte el valor de DateTime especificado en su representación de cadena equivalente.
	- Por ejemplo: 
		- Now.ToString(“dd-MM-yyyy”)
		- DateTimeVar.ToString("dd-MM-yyyy") - Proporciona el formato de fecha: 01-06-2022.

## ¿Qué es un Workflow?


Un ***Workflow/flujo de trabajo*** representa una parte relativamente pequeña de un proyecto de automatización, normalmente ejecutando una parte específica del proceso. Una vez construido, se puede reutilizar en diferentes proyectos.

Un flujo de trabajo está formado por actividades de Studio, interconectadas a través de variables para formar una rutina. La rutina normalmente tiene una entrada y una salida. Básicamente, define el flujo de automatización. De ahí el nombre, flujo de trabajo.

UiPath Studio le proporciona diseños de flujo de trabajo predefinidos para satisfacer todas las necesidades de un proceso de automatización rápido y confiable.

Los diseños de flujo de trabajo son:

- [**Sequences**](https://docs.uipath.com/studio/v2021.10/docs/sequences)
- [**Flowcharts**](https://docs.uipath.com/studio/v2021.10/docs/flowcharts)
- [**State Machines**](https://docs.uipath.com/studio/v2021.10/docs/state-machines)
- [**Global Exception Handler**](https://docs.uipath.com/studio/v2021.10/docs/global-exception-handler)


## ¿Qué son los Argumentos?

Los argumentos son muy similares a las variables:

- Almacenan datos de forma dinámica.
- Tienen los mismos tipos de datos.
- Soportan los mismos métodos y propiedades.

La diferencia es que **pasan datos entre flujos de trabajo y tienen una propiedad adicional para esto: *la dirección*.**  (Pasan datos entre padre y el hijo de los flujos de trabajo)

Mientras que las variables pasan data entre actividades, los argumentos pasan data entre automations. Como resultado, ellos permiten reutilizar ciertos proyectos una y otra vez.

Los argumentos tienen direcciones específicas: ==***In, Out y In/Out.*** ==
![[Pasted image 20230714075123.png]]
- **In:** se usan solo para pasar data en el workflow invocado
- **Out:** se usan solo para extraer data en el workflow invocado
- **In/Out:** funciona en ambas maneras
- **Property:** es usada para indicar que un argumento no está en uso actualmente, sin necesidad de eliminarlo de la lista

Estos le dicen al robot dónde se supone que debe ir la información almacenada en ellos.

### ¿Por qué son importantes?

Los argumentos son un componente clave cuando se trata de crear una automatización más compleja, donde necesita almacenar y usar datos entre múltiples flujos de trabajo.


## Crear Argumentos

Los nombres de los argumentos deben estar en PascalCase con un prefijo que indique la dirección del argumento, como in_DefaultTimeout, in_FileName, out_TextResult, io_RetryNumber.

Veamos las formas de crear argumentos.

1. **Desde el body de una Activity**
	- Haga clic con el botón derecho en un campo y seleccione Crear argumento de entrada o Crear argumento de salida en el menú contextual.
	- Alternativamente, presione Ctrl+M o Ctrl+Shift+M.
	- Se muestra el campo Establecer argumento.
	- Complete el nombre y presione Entrar. Se crea un argumento.
	- Compruebe su dirección y escriba en el panel Argumentos.

	1. Alternativamente, desde el Editor de expresiones:
		- Seleccione una parte de la expresión y presione *Ctrl+M (para argumentos de entrada) o Ctrl+Shift+M (para argumentos de salida).*
		- Luego se muestra el campo Establecer Arg.
		- Complete el nombre y presione Entrar. Se crea el argumento.
		- Compruebe su dirección y escriba en el panel Argumentos.
		- Los argumentos creados de esta forma reciben automáticamente el tipo según la actividad.
			![[Pasted image 20230714081449.png]]
	
2. **Desde el panel de Propiedades**

- Haga clic con el botón derecho en un campo que se pueda editar.
- Seleccione Crear argumento de entrada o Crear argumento de salida en el menú contextual. Alternativamente, presione *Ctrl+M (In) o Ctrl+Shift+M (Out).*
- Se muestra el campo *Set Arg*
- Complete el nombre y presione Entrar. El argumento se crea y es visible en el campo. Compruebe su dirección y escriba en el panel Argumentos.
- El tipo de argumento se genera automáticamente en función de la propiedad seleccionada.
![[Pasted image 20230714081859.png]]

3. **Desde el panel Argumentos**
	- Navegue hasta el panel Argumentos.
	- Seleccione la línea Crear argumento.
	- Rellene el nombre, la dirección y el tipo. Se crea un nuevo argumento.

# Arrays

## ¿Qué son las Colecciones?

Si tiene entradas de datos que son similares, como números de factura, nombres de libros y números de cuenta, y desea agruparlos, las colecciones son útiles. Son tipos de datos que permiten el almacenamiento de entradas del mismo tipo de datos base como elementos de una variable. 

De esta forma, puedes trabajar tanto con todos los objetos de la variable de colección como con cada objeto. Para que esto funcione, el nombre de la variable de colección y su posición en la colección pueden identificar los objetos de una *colección*.

Ejemplos de Arrays de Strings
```c#
StrArray = {"John", "Paul", "George", "Ringo"}

StrArray(0) = "John"
```

## ¿Qué es un Array?
Una variable de matriz o argumento es un tipo que permite almacenar múltiples valores del mismo tipo de datos. Piense en ello como un grupo de elementos con un tamaño que se define en la creación, y donde cada elemento se puede identificar por su índice.

En UiPath Studio, puede crear matrices de números, cadenas, valores booleanos, etc. Todas estas matrices son de tamaño fijo y no se pueden aumentar dinámicamente.

Por ejemplo: una matriz de meses de un año, una matriz de números impares entre uno y cien, etc.

## Business Scenarios donde se usan Arrays

- Cuando desee guardar los nombres de los meses en una variable.
- Cuando una colección fija de cuentas bancarias tiene que ser almacenada y utilizada en el proceso de pago.
- Cuando se tengan que tramitar todas las facturas pagadas en el mes anterior.
- Cuando se deba verificar en una base de datos los nombres de los empleados de una determinada unidad.
