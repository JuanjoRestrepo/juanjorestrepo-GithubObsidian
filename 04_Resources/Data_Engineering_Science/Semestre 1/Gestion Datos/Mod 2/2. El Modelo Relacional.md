# **1. ¿Qué es un Modelo?**

- Un **modelo** es una representación abstracta de un sistema real que nos ayuda a entender su estructura y comportamiento.
- En el contexto de bases de datos, un modelo permite comprender de forma conceptual o lógica cómo están organizados los datos dentro de la base de datos.

# 2. **¿Qué es un Modelo Relacional?**

Un **Modelo Relacional** es un modelo lógico que representa una base de datos relacional mediante tablas, sus campos y las relaciones entre ellas. Es una herramienta utilizada por ingenieros de datos para diseñar la base de datos, la cual luego será implementada físicamente en un **Sistema Gestor de Base de Datos Relacional (RDBMS)**.

Aunque los **ingenieros de datos** son responsables de la creación y gobernanza de los datos, los **científicos de datos** no lo son. 

***Los científicos de datos trabajan con bases de datos ya existentes,*** realizando consultas para procesar los datos y aplicar algoritmos como **machine learning**. Para ellos, el **Modelo Relacional** es más bien una guía que muestra cómo están organizados los datos, facilitando las consultas.

# **3. Conceptos importantes**

#### **Tabla**
Las **tablas** son el núcleo de una base de datos relacional y se componen de filas y columnas:

- **Filas**: Representan los registros o datos almacenados.
- **Columnas**: Representan los atributos de cada registro.

Por ejemplo, una tabla llamada **Libros** contiene los atributos `id_libro`, `nombre`, `paginas`, `fecha_publicacion` e `id_editorial`. Estos atributos son las columnas, y cada registro en esta tabla corresponde a un libro con valores en cada uno de esos atributos.

**![[Pasted image 20241015165307.png]]**
Este pequeño recuadro, cuyo nombre es Libros, es la representación lógica de la tabla Libros. Como podemos observar, la tabla contiene cinco atributos: id_libro, nombre, paginas, fecha_publicacion y id_editorial. Esto quiere decir que la tabla tiene cinco columnas donde se registran los valores de estos atributos. En el Sistema Gestor de la Base de Datos Relacional, la tabla se vería más o menos así.

![[Pasted image 20241015165322.png]]
Esta tabla contiene dos libros registrados: Juego de Tronos y Segunda Fundación. Para cada uno de ellos se registran un identificador, su nombre, el número de páginas y su fecha de publicación. Aquí podremos notar algo interesante: la editorial está representada por un número en lugar de un nombre.


#### **Tipo de dato**
Cada columna de una tabla tiene un **tipo de dato**, que define el tipo de valor que puede contener. Ejemplos:

- **INT**: Enteros, como el `id_libro` o `paginas`.
- **VARCHAR2(100)**: Cadenas de texto de hasta 100 caracteres, como el nombre del libro.
- **DATE**: Fechas, como `fecha_publicacion`.

Los tipos de datos son esenciales en **Ciencia de Datos**, ya que definen cómo podemos manipular y analizar los datos.

### **Llave primaria (PK)**
La **Llave Primaria** es un identificador único para cada registro de una tabla, similar a un "documento de identidad". Su función es asegurar que cada registro sea único, evitando la redundancia. Además, las llaves primarias permiten implementar relaciones entre tablas en una base de datos relacional.

Por ejemplo, en la tabla **Libros**, el atributo `id_libro` es la llave primaria.

### **Llave foránea (FK)**
Una **Llave Foránea (Foreign Key)** es un identificador en una tabla que hace referencia a una llave primaria de otra tabla. Las llaves foráneas permiten relacionar registros de distintas tablas, asegurando la consistencia de los datos.

En la tabla **Libros**, `id_editorial` es una llave foránea que se refiere a la llave primaria `id_editorial` en la tabla **Editoriales**. Así, cada libro está asociado a una editorial, pero una editorial puede estar asociada a varios libros.

### **Relación**
Una **Relación** conecta tablas a través de llaves foráneas. En el modelo relacional, estas relaciones vinculan registros de una tabla con registros de otra tabla. Por ejemplo, en la relación entre **Libros** y **Editoriales**, un libro está relacionado con una única editorial a través de la columna `id_editorial`.

![[Pasted image 20241015165619.png]]

Las tablas Libros y Editoriales se encuentran unidas por una línea, lo que indica una relación entre ellas. Por convención, normalmente los profesionales encargados del diseño de una base de datos le colocan el mismo nombre tanto al campo que representa la llave foránea como al campo que representa la llave primaria en la otra tabla. Lo anterior lo podemos evidenciar en el nombre `id_editorial`

![[Pasted image 20241015165627.png]]'

En este caso podemos identificar que un libro se relaciona únicamente con una editorial ya que en el campo `id_editorial` tenemos permitido colocar solamente un única llave foránea por registro.

Pero, lo anterior no quiere decir que yo no pueda repetir el valor de una llave foránea en diferentes registros. Por ejemplo, para un tercer libro, de nombre ***Tormenta*** de Espadas, el `id_editorial` podría volver a ser `2`

Desde el punto de vista de las editoriales se puede decir que una editorial tiene ***la facultad de editar y publicar varios libros***. Lo que acabamos de describir se conoce como ***Cardinalidad.***

### **Cardinalidad**
La **Cardinalidad** define cuántos registros de una tabla están vinculados a registros de otra tabla. Existen tres tipos principales de cardinalidad:

#### **1. Cardinalidad 1:1**
Cada registro en la tabla A se relaciona con un único registro en la tabla B, y viceversa.

#### **2. Cardinalidad 1**
Un registro en la tabla A se relaciona con varios registros en la tabla B, pero cada registro en la tabla B se relaciona con un único registro en la tabla A. Por ejemplo, una editorial (tabla B) puede publicar varios libros (tabla A), pero cada libro pertenece a una sola editorial.

#### **3. Cardinalidad 1:N**
Esta cardinalidad nos indica que para dos tablas relacionadas A y B, los registros de la tabla A se relacionan con varios registros de la tabla B, mientras que los registros de la tabla B se relacionan con un único registro de la tabla B. En este caso, la llave primaria de los registros de la tabla A se convierte en llave foránea en los registros de la tabla B. En nuestro Modelo Relacional ya vimos este tipo de cardinalidad en la relación entre Libros y Editoriales.

#### **4. Cardinalidad N:M** 
También llamada cardinalidad muchos a muchos, nos indica que para dos tablas relacionadas A y B, los registros de la tabla A se relacionan con varios registros de la tabla B, y los registros de la tabla B se relacionan con varios registros de la tabla A. Este tipo de cardinalidad se puede reconocer por la presencia de una tabla intermedia C entre las tablas A y B. En Nuestro Modelo Relacional tenemos como ejemplo la relación entre las tablas Autores y Libros, misma que se muestra a continuación.

![[Pasted image 20241015170231.png]]

Aquí la ***tabla C*** sería `Autores_Libros`. ***Esta tabla intermedia tiene la responsabilidad de contener llaves foráneas que referencian a las dos tablas*** que hacen parte de la relación. 
Para el ejemplo, el significado es: un autor puede escribir uno o más libros y un libro puede ser escrito por uno o varios autores.

### **Normalización**
La **Normalización** es un conjunto de reglas que estructuran una base de datos relacional para reducir la redundancia y asegurar la consistencia de los datos. Las formas normales más importantes son:

#### **Primera Forma Normal (1FN)**
- Cada tabla debe tener una **llave primaria**.
- Los datos deben ser **atómicos**, es decir, no divisibles en otros datos.
- Las columnas no deben variar continuamente, sino que, si esto sucede, esos datos deben ser registrados en una nueva tabla.

#### **Segunda Forma Normal (2FN)**
- Cumple con la 1FN y además, todos los atributos de la tabla deben depender de la llave primaria.
- Si un atributo no depende completamente de la llave primaria, se debe mover a una nueva tabla.

#### **Tercera Forma Normal (3FN)**
- Cumple con la 2FN y además elimina los atributos que no dependan directamente de la llave primaria.
- Cada atributo debe depender únicamente de la llave primaria y no de otros atributos.
