**Antes de sumergirnos en la plantilla de Robotic Enterprise Framework (REFramework), revisemos los tipos de procesos comerciales desde la perspectiva del procesamiento de transacciones. Y recordemos también el concepto de transacción.**

Los procesos de negocio pueden será muy diferentes entre sí. Pero generalmente es posible clasificarlos en función de cómo repiten ciertos pasos al procesar datos.

Al considerar estos pasos y cómo se repiten, podemos dividir los procesos comerciales en tres categorías:

## 1. Linear
____________________________________
Los pasos del proceso se realizan una sola vez. Si la necesidad es procesar datos diferentes, entonces la automatización debe ejecutarse nuevamente. Por ejemplo, una solicitud de correo electrónico que ingresa desencadena una automatización que recopila datos y proporciona una respuesta al remitente. El proceso se ejecuta para cada correo electrónico individual.

Los procesos lineales suelen será simples y fáciles de implementar, pero no muy adecuados para situaciones que requieren repeticiones de pasos utilizando diferentes datos.

![[Pasted image 20230728082120.png|200]]

## 2. Iterative
____________________________________
Los pasos del proceso se realizan varias veces, pero cada vez se utilizan diferentes elementos de datos. Por ejemplo, en lugar de leer un solo correo electrónico en cada ejecución, la automatización puede recuperar varios correos electrónicos e iterarlos siguiendo los mismos pasos.

La implementación de este proceso se realiza con un bucle simple. Pero tiene una desventaja: si ocurre un problema mientras se procesa un elemento, todo el proceso se interrumpe y el resto de los elementos permanecen sin procesar.

![[Pasted image 20230728082223.png|200]]

## 3. Transactional
____________________________________
De manera similar a los procesos iterativos, los pasos de los procesos transaccionales se repiten varias veces en diferentes elementos de datos. Sin embargo, el diseño de automatización es tal que cada parte repetible se procesa de forma independiente.

Estas partes repetibles se denominan transacciones. Las transacciones son independientes entre sí porque no comparten ningún dato ni tienen un orden particular para será procesadas.

![[Pasted image 20230728082304.png|300]]

Las tres categorías de procesos pueden verse como etapas de madurez de un proyecto de automatización. Comenzando con tareas lineales simples, que pasan por múltiples repeticiones y, finalmente, evolucionan hacia un enfoque transaccional.

Sin embargo, esta no es una regla para todos los casos, y la categoría debe elegirse de acuerdo con las características del proceso (p. ej., datos que se procesan y frecuencia de repeticiones) y otros requisitos relevantes (p. ej., facilidad de uso y robustez).

La plantilla REFramework se puede utilizar para manejar cualquier tipo de los procesos anteriores. En su versión lista para usar, está diseñado para abordar procesos transaccionales.

# What is a Transaction?
____________________________________
Una transacción representa la cantidad mínima (atómica) de datos y los pasos necesarios para procesar los datos, mediante el cumplimiento de una sección de un proceso empresarial. Un ejemplo típico sería un proceso que lee un solo correo electrónico de un buzón y extrae datos de él.

Llamamos a los datos atómicos porque una vez que se procesan, se supone que ya no los necesitamos a medida que avanzamos con el proceso comercial.

## ¿Cuáles son algunos escenarios comerciales en los que usaré el procesamiento de transacciones?

- Necesita leer datos de varias facturas que están en una carpeta e ingresar esos datos en otro sistema. Cada factura puede verse como una transacción, porque hay un proceso repetitivo para cada una de ellas (es decir, extraer los datos e ingresarlos en otro lugar).

- Hay una lista de personas y sus direcciones de correo electrónico en una hoja de cálculo, y se debe enviar un correo electrónico a cada uno de ellos junto con un mensaje personalizado. Los pasos de este proceso (es decir, obtener datos de la hoja de cálculo, crear un mensaje personalizado y enviar un correo electrónico) son los mismos para cada persona, por lo que cada fila de la hoja de cálculo se puede considerar una transacción.
    
- Al buscar un nuevo apartamento, se puede utilizar un robot para realizar una búsqueda de acuerdo con algunos criterios. Para cada resultado de la búsqueda, el robot extrae la información sobre la propiedad e inserta los datos en una hoja de cálculo. En este caso, la página de detalles de cada propiedad constituye una transacción.

**Aunque el caso de uso más común de REFramework es un proceso transaccional desatendido con una cola como entrada de datos, la plantilla se puede usar en casi todos los escenarios:**

- Ingrese datos de una cola en Orchestrator o de una fuente diferente (por ejemplo, archivo de Excel, buzón de correo, otra aplicación).
- Proceso transaccional o lineal (es decir, un proceso con una sola transacción).
- Procesos de negocio desatendidos.
