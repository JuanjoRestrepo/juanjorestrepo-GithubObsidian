Al considerar estos pasos y cómo se repiten, podemos dividir los procesos comerciales en tres categorías: lineales, iterativos y transaccionales.


## Linear
_______________________________________________________________
Los pasos del proceso se realizan una sola vez. Si la necesidad es procesar datos diferentes, la automatización debe ejecutarse nuevamente. Por ejemplo, una solicitud de correo electrónico que ingresa desencadena una automatización que recopila datos y proporciona una respuesta al remitente. El proceso se ejecuta para cada correo electrónico individual.

Los procesos lineales suelen será simples y fáciles de implementar, pero no muy adecuados para situaciones que requieren repeticiones de pasos utilizando diferentes datos.

![[Pasted image 20230725100559.png|200]]

## Iterative
_______________________________________________________________
Los pasos del proceso se realizan varias veces, pero cada vez se utilizan diferentes elementos de datos. Por ejemplo, en lugar de leer un solo correo electrónico en cada ejecución, la automatización puede recuperar varios correos electrónicos e iterarlos siguiendo los mismos pasos.

La implementación de este proceso se realiza con un bucle simple. Pero tiene una desventaja: si ocurre un problema mientras se procesa un elemento, todo el proceso se interrumpe y el resto de los elementos permanecen sin procesar.

![[Pasted image 20230725100646.png|200]]

## Transactional
_______________________________________________________________
Similar to iterative processes, the steps of transactional processes repeat multiple times over different data items. However, the automation design is such that each repeatable part processes independently.

These repeatable parts are then called transactions. Transactions are independent from each other because they do not share any data or have any particular order to be processed.

![[Pasted image 20230725100715.png|350]]

The three categories of processes can be seen as the maturity stages of an automation project. Starting with simple linear tasks, which go through multiple repetitions, and finally, evolve into a transactional approach.

However, this is not a rule for all cases, and the category should be chosen according to the characteristics of the process (e.g., data being processed and frequency of repetitions) and other relevant requirements (e.g., ease of use and robustness).

# ¿Qué es una transacción?
_______________________________________________________________
Una transacción representa la cantidad mínima (atómica) de datos y los pasos necesarios para procesar los datos, mediante el cumplimiento de una sección de un proceso empresarial. Un ejemplo típico sería un proceso que lee un solo correo electrónico de un buzón y extrae datos de él.

Llamamos a los datos atómicos porque una vez que se procesan, se supone que ya no los necesitamos a medida que avanzamos con el proceso comercial.

## ¿Cuáles son algunos escenarios comerciales en los que usaré el procesamiento de transacciones?
_______________________________________________________________
Debe leer datos de varias facturas que están en una carpeta e ingresar esos datos en otro sistema. Cada factura puede verse como una transacción, porque hay un proceso repetitivo para cada una de ellas (es decir, extraer los datos e ingresarlos en otro lugar).

Hay una lista de personas y sus direcciones de correo electrónico en una hoja de cálculo, y se debe enviar un correo electrónico a cada uno de ellos junto con un mensaje personalizado. Los pasos de este proceso (es decir, obtener datos de la hoja de cálculo, crear un mensaje personalizado y enviar un correo electrónico) son los mismos para cada persona, por lo que cada fila de la hoja de cálculo se puede considerar una transacción.

Al buscar un nuevo apartamento, se puede utilizar un robot para realizar una búsqueda de acuerdo con algunos criterios. Para cada resultado de la búsqueda, el robot extrae la información sobre la propiedad e inserta los datos en una hoja de cálculo. En este caso, la página de detalles de cada propiedad constituye una transacción.
