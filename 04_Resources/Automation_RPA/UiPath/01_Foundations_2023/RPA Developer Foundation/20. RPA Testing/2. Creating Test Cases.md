UiPath Test Suite ofrece una solución completa para las pruebas de RPA durante el desarrollo de la automatización, así como durante la integración y antes de pasar a producción. Según el modelo de implementación, las pruebas de RPA se pueden integrar en un entorno de integración continua.

Pero el primer objetivo de las pruebas de RPA, al menos cronológicamente, es abordar los problemas de aplicaciones y de automatización lo antes posible, en la fase de desarrollo de RPA.

Los casos de prueba son una de las características de Studio que le permiten probar sus automatizaciones a medida que las desarrolla.

## La estructura de un caso de prueba
_________________________________________________________
La forma más sencilla de crear un caso de prueba de RPA es hacer clic con el botón derecho en un flujo de trabajo en el panel Proyecto y seleccionar "Crear caso de prueba". El caso de prueba así creado tendrá la estructura de desarrollo impulsada por el comportamiento.

## Test Case:
_________________________________________________________
According to the behavior-driven development model, a test case is made of three distinct sections:

1. **Given Section:** Este bloque es donde se realiza la inicialización para que el caso de prueba funcione correctamente.
	Este bloque es donde se realiza la inicialización para que el caso de prueba funcione correctamente.
2. **When Section:** Por lo general, aquí es donde se invoca y ejecuta el flujo de trabajo de RPA con los datos de prueba de entrada.
	Debe contener el alcance de la prueba, más precisamente, los pasos exactos necesarios para ejecutar su caso de prueba.
3. **Then Section:** Este bloque es el punto de verificación. Es donde los datos de salida del caso de prueba se verifican con el resultado esperado, generalmente utilizando las actividades dedicadas en el paquete de prueba.

## Las actividades de verificación
_________________________________________________________
Estas actividades están destinadas a será utilizadas en el bloque Entonces, para verificar los resultados de la ejecución de un caso de prueba.

### Verify Expression
This activity verifies a single expression (e.g. whether two variables are equal). Its outcome can be True or False.
![[Pasted image 20230727144027.png]]

### Verify Expression with Operator
This activity compares the outcomes of two expressions, variables or arguments using six predefined operators. Its outcome can also be True or False.

### Verify Control Attribute
This is the most versatile activity in the Testing Activities Package. It allows the comparison of a property returned by another Activity with an expression, variable or argument. Its outcome can also be True or False.
