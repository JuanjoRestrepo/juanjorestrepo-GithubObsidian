
# Source Systems (Sistema de Fuente) en Data Pipelines

### Tipos Comunes de Sistemas Fuente (En este curso):
* **Archivos CSV**: Un formato de texto plano muy común para datos tabulares. Fáciles de leer y escribir. 
* **Archivos Parquet**: Formato de almacenamiento columnar optimizado para el análisis de big data. Eficiente en almacenamiento y rendimiento de lectura para consultas analíticas. 
* **Archivos JSON**: Formato ligero de intercambio de datos, a menudo usado para datos semiestructurados y APIs. 
* **Bases de datos SQL**: Sistemas de gestión de bases de datos relacionales (RDBMS) como PostgreSQL, MySQL, SQL Server, etc. Almacenan datos estructurados en tablas. 

### Otros Orígenes Comunes de Datos: 
* **APIs (Application Programming Interfaces)**: Permiten la comunicación entre diferentes sistemas de software. Los datos se extraen haciendo solicitudes a servicios web. 
* **Data Lakes**: Grandes repositorios de datos brutos, sin procesar, que pueden incluir datos estructurados, semiestructurados y no estructurados. 
* **Data Warehouses**: Aunque a menudo son el destino final de los datos transformados en ETL/ELT, también pueden ser sistemas fuente si se extraen datos ya consolidados para análisis adicionales o para otros procesos. 
* **Web Scraping**: La técnica de extraer datos de sitios web utilizando bots o scripts.


## Reading in parquet files

- Formato Open Source
- Orientado a columnas
- Diseñado para el almacenamiento y recuperación de campos eficientes
- Similar a trabajar con CSV, pero son más rápidos para lectura y escritura

```python
import pandas as pd

# Read the parquet file into memory
raw_stock_data = pd.read_parquet("raw_stock_data.parquet", engine="fastparquet")
```

## Connecting to SQL databases

Este código demuestra cómo establecer una conexión a una base de datos SQL (en este caso, PostgreSQL) utilizando las librerías `sqlalchemy` y `pandas`

```python
import sqlalchemy
import pandas as pd

# Connection URI: schema_identifier://username:password@host:port/db
connection_uri = "postgresql+psycopg2://repl:password@localhost:5432/market"
db_engine = sqlalchemy.create_engine(connection_uri)
```

1. **URI de Conexión (`connection_uri`)**: *
- `connection_uri = "postgresql+psycopg2://repl:password@localhost:5432/market"` 
* Este es un string que define la cadena de conexión a la base de datos. Sigue un formato estándar:
	* `schema_identifier`: `postgresql+psycopg2` indica el dialecto de la base de datos (PostgreSQL) y el driver que se usará (`psycopg2` en este caso). 
	* `username`: `repl` es el nombre de usuario para autenticarse en la base de datos. 
	* `password`: `password` es la contraseña del usuario. 
	* `host`: `localhost` es la dirección del servidor donde se ejecuta la base de datos. Podría ser una IP o un nombre de dominio. 
	* `port`: `5432` es el número de puerto por defecto para PostgreSQL. 
	* `db`: `market` es el nombre de la base de datos específica a la que se desea conectar. 


1. **Creación del Motor de Base de Datos (`db_engine`)**: *
	- `db_engine = sqlalchemy.create_engine(connection_uri)`
	- La función `sqlalchemy.create_engine()` toma la URI de conexión y devuelve un objeto "engine".
	- Este `engine` actúa como el punto de entrada principal para interactuar con la base de datos desde Python. Maneja la creación de conexiones y la traducción de sentencias SQL.

```python
raw_stock_data = pd.read_sql("SELECT * FROM raw_stock_data LIMIT 10", db_engine)
```

## Modularidad

Separar la lógica en funciones

- Aumenta la legibilidad dentro de una canalización
- Se adhiere al principio PEP-8 "No Repetirse a Uno Mismo"
- Este principio, permite reutilizar código
- Agilizar troubleshooting

```python
def extract_from_sql(connection_uri, query):
    # Create an engine, query data and return DataFrame
    db_engine = sqlalchemy.create_engine(connection_uri)
    return pd.read_sql(query, db_engine)

extract_from_sql("postgresql+psycopg2://.../market", "SELECT ... LIMIT 10;")
```
