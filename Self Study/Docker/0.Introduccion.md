# 1. Antes

1. Se creaban aplicaciones, ya sea con `django`, `postgres`, `rex`, etc... se requeria instalarlo en su propio server para **aislar las dependencias**
2. Esto era para ahorrar recursos

![[AntesDocker.png|500]]

## La matriz del infierno

3. Los servicios debian separarse. Pero para cada aplicación, se necesitaban **librerías especificas**.
4. Si todo esto se instalaba en el mismo server, podrían haber **problemas de versiones, entre OS**

![[MatrizDelInfierno.png|450]]
*"En mi maquina funciona"*

## Virtual Machines - Primera solucion

5. Lograba aislar las aplicaciones y lo de la matriz del demonio
6. **Las dependencias, el OS y todo se aislaba** y no creaba conflictos entre versiones, OS, etc...
7. Lo malo, es que las **VM son muy pesadas y lentas** de inicializar al tener que cargar todo un OS desde cero.
8. Esto necesitaba utilizar muchos recursos

![[VirtualMachine Primera Solucion.png|450]]

## Docker - La salvacion
9. Docker es la manera para crear un aislamiento entre aplicaciones
10. Ya no crea conflictos gracias a las `Containers`
11. Los Containers **almacenan las aplicaciones con sus librerías, dependencias**
12. Es mas ligero que una VM
13. Permite definir una única configuración. Se define una sola vez y así es posible replicarla fácilmente
14. **Comparten el mismo Kernel** sobre el OS que se este ejecutando

![[Docker1.png|450]]

## Linux Basics

15. Se tiene el **Kernel el cual interactua con el Hardware de la maquina**
16. Y este **Kernel-Core, corre y se comparte entre diferentes versiones de Linux** como Ubuntu, Fedora, etc...

![[OS Linux y Kernel.png|450]]

### Ejemplo:

![[Ejemplo Fedora.png|450]]

- Asumimos que tenemos el `OS Fedora` y le instalamos `Docker Engine`, **podríamos contenerizar cualquier distribución** de Linux. *Ubuntu, Arch, CentOS*
- Esto es **gracias al Kernel que comparten** entre cada distribución de Linux

### Windows Containers

![[Windows Containers.png|450]]

- Hay que **tener cuidado con los contenedores y sus respectivos Kernels**
- **No es posible ejecutar** Contenedores creados con el Kernel de Windows sobre el Kernel de Linux
- Una solución posible es usar `Docker Desktop`

## VM vs Containers

![[VM vs Containers.png]]

| Característica           | Máquinas Virtuales (VM)                                            | Contenedores                                                          |
| ------------------------ | ------------------------------------------------------------------ | --------------------------------------------------------------------- |
| **Definición**           | SO completo virtualizado sobre hipervisor                          | Paquete de app + dependencias (comparte kernel)                       |
| **Nivel de abstracción** | Hardware virtualizado                                              | Sistema operativo (nivel aplicación)                                  |
| **Recursos**             | Alto consumo (CPU/RAM por SO completo)                             | Bajos recursos (comparte kernel del host)                             |
| **Tiempo de inicio**     | Minutos (arranque de SO)                                           | Segundos/milisegundos                                                 |
| **Aislamiento**          | Total (kernel dedicado)                                            | Parcial (procesos aislados)                                           |
| **Imagen**               | Grande (GBs, incluye SO completo)                                  | Ligera (MBs, solo app/dependencias)                                   |
| **Portabilidad**         | Limitada (depende del hipervisor)                                  | Alta (misma imagen en cualquier entorno)                              |
| **Casos de uso clave**   | - Apps críticas con SO distintos<br>- Entornos de alto aislamiento | - Microservicios<br>- CI/CD<br>- Escalado rápido<br>- Desarrollo ágil |
| **Ejemplos**             | VMware, VirtualBox, Hyper-V                                        | Docker, Podman, Kubernetes                                            |

## Ejemplo con Enginex

```bash
docker run --name test -d -p 8080:80 nginx:latest
```
- `docker run:` ejecutar
- `--name test: `nombre del contenedor es **test**
- `-d`: se hace **detach de la interfaz gráfica** para no bloquear la consola
- `-p 8080:80`: port mapping para que todo el tráfico que llega sobre el **puerto 8080** se redirija al **puerto 80**
- `nginx:latest`: se define sobre **lo que nos basaremos para crear al contenedor** test. En este caso, *nginx siendo la ultima version*
