## Lesson Objectives
* Master the implementation of the **Add Queue Item** activity within a Dispatcher workflow.
* Learn how to push structured transaction payloads and enforce reference uniqueness in UiPath Orchestrator Queues.

---

## Step-by-Step Implementation Guide

### 1. Prepare the Dispatcher Workflow
* Ensure your **Dispatcher** project is initialized in UiPath Studio.
* Validate that target data collection mechanisms (e.g., looping through files, reading database rows, or parsing APIs) are established.

### 2. Insert the `Add Queue Item` Activity
* Open the **Activities Panel** in UiPath Studio.
* Search for **Add Queue Item** (`UiPath.Core.Activities.AddQueueItem`).
* Drag the activity into the data collection loop (e.g., inside the `Body` of a **For Each** loop).

### 3. Configure Activity Properties
* **QueueName**: Specify the exact string name of the target Orchestrator queue (e.g., `"Invoice_Queue"`).
* **ItemInformation (ItemInfo)**: Map payload key-value pairs (`In` direction) to pass contextual transaction data to the queue:
  * `Name`: Key string (e.g., `"FilePath"`, `"InvoiceNumber"`, `"CustomerEmail"`).
  * `Value`: Corresponding variable or expression (e.g., `currentFile.FullName`, `str_InvoiceNum`).

### 4. Configure Unique References (Optional)
* Populate the **Reference** property field with a unique business key (e.g., `str_InvoiceNum` or `currentFile.Name`).
* Ensure **Enforce Unique References** is enabled on the target queue in Orchestrator to prevent duplicate item entries.

### 5. Validate & Execute
* Save the workflow (`Ctrl + S`).
* Run the Dispatcher process to push items to Orchestrator.
* Access **Orchestrator > Queues > View Transactions** to verify that items display with status **New**.

---

## Conclusion
Configuring the **Add Queue Item** activity allows Dispatcher workflows to publish structured data payloads seamlessly into Orchestrator Queues. This architecture provides the foundation for asynchronous, decoupled processing by downstream Performer bots.
