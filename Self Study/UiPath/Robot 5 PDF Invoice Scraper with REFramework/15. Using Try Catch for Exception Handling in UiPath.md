
# Using Try Catch for Exception Handling in UiPath

## Lesson Objectives
* Master the implementation of the **Try Catch** activity to handle runtime exceptions gracefully.
* Learn to structure robust error handling using **Try**, **Catch**, and **Finally** blocks to maintain workflow execution control.

---

## Architectural Breakdown of Try Catch

* **Try**: Houses core business activities that might encounter runtime errors (e.g., file I/O, UI selector failures, network timeouts).
* **Catches**: Defines specific exception handlers (e.g., `System.Exception`, `SelectorNotFoundException`, `IOException`) to execute fallback logic or error logging when an error occurs in the Try block.
* **Finally**: Optional execution block containing cleanup actions (e.g., closing open applications or database connections) that execute **regardless** of whether an exception was thrown or caught.

---

## Step-by-Step Implementation Guide

### 1. Add `Try Catch` to Workflow
* Search for **Try Catch** (`UiPath.Core.Activities.TryCatch`) in the **Activities Panel**.
* Drag and drop the activity into the target workflow section.
* *Shortcut*: Right-click existing activity sequences and select **Surround with Try Catch** (`Ctrl + T`).

### 2. Configure the `Try` Block
* Place vulnerable activities inside the **Try** section (e.g., `Read CSV`, `Click`, or `HTTP Request`).

### 3. Configure the `Catches` Block
* Click **Add New Catch** and select the appropriate exception type (typically `System.Exception` for general errors or specific subtypes for precise handling).
* Insert handling logic inside the Catch block:
  * Drag a **Log Message** activity into the catch area.
  * Set **LogLevel** to `Error`.
  * Define the log message string to capture diagnostic details:
    ```vb
    "Error occurred: " + exception.Message + " at " + exception.Source
    ```

### 4. Configure the `Finally` Block (Optional)
* Add cleanup tasks that must execute continuously regardless of pass/fail outcome (e.g., `Kill Process` or `Close Application`).

### 5. Validate & Test
* Configure activity properties like **ContinueOnError** carefully (setting `ContinueOnError = False` ensures errors bubble up to the Try Catch block).
* Execute tests with invalid inputs or missing assets to verify that the Catch block intercepts errors cleanly without unhandled crashes.

---

## Conclusion
Implementing **Try Catch** blocks is a fundamental practice in UiPath development that prevents unhandled execution crashes, captures operational telemetry, and ensures workflows fail gracefully or recover automatically.
