# Creating a New Queue in UiPath Orchestrator

## Lesson Objectives
* Learn how to create and configure an Orchestrator Queue to store transaction items produced by a Dispatcher bot and consumed by a Performer bot.
* Understand queue configuration parameters such as **Unique References** and target folder organization.

---

## Step-by-Step Configuration Guide

### 1. Access the Orchestrator Queues Panel
* Log in to your **UiPath Orchestrator** tenant via browser.
* Select the correct target folder from the left navigation panel (e.g., **Operations** folder).
* Navigate to the **Queues** tab within the folder view.

### 2. Initialize Queue Creation
* Click the **Add Queue** button (or **+** icon) on the top action bar to open the creation modal.

### 3. Configure Queue Properties
* **Name**: Enter a descriptive, standard name (e.g., `Invoice_Queue` or `Receipts_Processing_Queue`).
* **Description**: Add brief metadata explaining the item payload (e.g., *"Contains file paths and extraction data for PDF invoices"*).
* **Unique References**: Toggle or check **Enforce Unique References** if you want Orchestrator to prevent adding duplicate transaction items based on a custom reference key.
* **Auto Retry**: Configure retry limits for application exceptions if needed.

### 4. Save & Deploy
* Click **Save** to create the queue. Verify that the new queue status displays as **Active** in the Queues list.

### 5. Integration with Dispatcher Bot (`Add Queue Item`)
* Open your **Dispatcher project** in **UiPath Studio**.
* Drag an **Add Queue Item** activity into your data ingestion loop.
* Configure activity properties:
  * **QueueName**: Select or enter the exact name of the created queue (e.g., `"Invoice_Queue"`).
  * **ItemInformation**: Define key-value pairs (`In` arguments) containing transaction data (e.g., `FilePath`, `InvoiceID`).
  * **Reference**: Bind a unique string identifier to enforce tracking and deduplication.

---

## Conclusion
Setting up an Orchestrator Queue creates a centralized work queue that decouples data ingestion from business logic processing. This establishes the foundation for multi-bot scalability and robust error handling in enterprise RPA workflows.
