## Principios de REST

![[Screenshot 2025-03-21 at 6.41.49 PM.png | 600|centered]]

- **Recursos:** Cada recurso se identifica con una URL

- **Interfaz Uniforme:** 
- **Separación de conceptos:** Permite que el cliente y servidor evolucionen de forma separada.

### `path-to-regexp`  
**Librería JS para convertir patrones de rutas en expresiones regulares.**  
#### **Qué hace**:  
- Convierte rutas como `/user/:id` → **RegExp**.  
- Extrae parámetros dinámicos de URLs (`/user/123` → `{ id: "123" }`).  
- Genera URLs a partir de patrones y datos.  
#### **Cómo funciona**:  
```javascript
const { pathToRegexp } = require("path-to-regexp");  
const regex = pathToRegexp("/user/:id");  
// Regex: /^\/user(?:\/([^\/#\?]+?))[\/#\?]?$/i  
```
#### **Sintaxis básica**:

- **`:param`**: Parámetro dinámico (ej: `:id`).
- **`*`**: Coincide con cualquier cosa (ej: `/files/*`).
- **`?`**: Parámetro opcional (ej: `/:id?` → `id` opcional).

```javascript
const url = "/user/456";  
const match = regex.exec(url);  
console.log(match[1]); // Output: "456"  
```

**Nota: No se recomienda hacer Regex manualmente**

app.get('/movies', (req, res) => {
	const { genre } = req.query;
	if (genre) {
	
		const filteredMovies = movies.filter(
		
		(movie) =>
		
		movie.genre.some((g) => g.toLowerCase() === genre.toLowerCase()) //comparamos el genero de la pelicula con el genero que nos pasan en minusculas
		);
		return res.json(filteredMovies);
	}

# POST vs PUT vs PATCH

# Idempotencia 🌀
Es una **Propiedad** → Realizar una acción múltiples veces y obtener siempre el mismo resultado que al ejecutarla una vez.

![[Screenshot 2025-03-22 at 6.24.35 PM.png|centered]]
## Métodos HTTP Relacionados

### POST 📩
```json
{
  "Acción": "Crear nuevo elemento/recurso",
  "Ruta Ejemplo": "/movies",
  "Idempotente": "No ❌",
  "Razón": "Cada solicitud crea un recurso nuevo"
}
```

### PUT 🔄
```json
{
  "Acción": "Actualizar totalmente un recurso existente (o crearlo si no existe)",
  "Ruta Ejemplo": "/movies/123-456-789",
  "Idempotente": "Sí ✅",
  "Razón": "Múltiples ejecuciones producen el mismo estado final"
}
```
### PATCH 🩹
```json
{
  "Acción": "Actualización parcial de un recurso",
  "Ruta Ejemplo": "/movies/123-456-789",
  "Idempotente": "Depende ⚠️",
  "Razón": "La idempotencia depende de la implementación específica"
}
```

## ⚠️ Errores Comunes

- **Usar PUT para actualizaciones parciales** → Debes usar PATCH.
- **Asumir que PATCH es siempre idempotente** → Requiere implementación cuidadosa.
- **No validar campos en PATCH** → Riesgo de corrupción de datos.

---

## 💡 Consejos para APIs REST

- Usa **POST** cuando no conozcas el URI final del recurso.
- Usa **PUT** cuando controles el cliente y el URI (ej: sistemas internos).
- Incluye **ETags** en PATCH para evitar conflictos de concurrencia.

# CORS 🌐

**Definición**: Mecanismo de seguridad que permite a un servidor restringir recursos (APIs, fuentes, scripts) desde dominios diferentes al suyo.

---
## 🔑 Conceptos Clave
- **Origen (Origin)**: Combinación de protocolo, dominio y puerto (ej: `https://midominio.com:443`).
- **Política Same-Origin**: Bloquea peticiones entre orígenes distintos (por defecto en navegadores).
- **Preflight**: Petición `OPTIONS` previa para verificar permisos en métodos complejos (PUT, DELETE, etc).

---
## 🛡️ ¿Cómo funciona?
1. **Cliente** envía petición con cabecera `Origin`.
2. **Servidor** responde con:
   - `Access-Control-Allow-Origin`: Orígenes permitidos (`*` para todos).
   - `Access-Control-Allow-Methods`: Métodos HTTP autorizados (GET, POST, etc).
   - `Access-Control-Allow-Headers`: Cabeceras permitidas (Content-Type, Authorization).
3. **Navegador** bloquea la respuesta si el origen no está autorizado.

---
## 🧩 Tipos de Peticiones CORS

### 1. Simple Request
- Métodos: GET, HEAD, POST.
- Cabeceras permitidas: `Accept`, `Accept-Language`, `Content-Language`, `Content-Type` (solo `text/plain`, `multipart/form-data`, `application/x-www-form-urlencoded`).
### 2. Preflight Request
```http
OPTIONS /api/data HTTP/1.1
Origin: https://cliente.com
Access-Control-Request-Method: PUT
Access-Control-Request-Headers: X-Custom-Header
```
