    user_handle VARCHAR(50) NOT NULL UNIQUE,

# Análisis de Código SQL - Base de Datos Twitter

## 1. Creación de la Base de Datos (`CREATE DATABASE`)

- **Acción**: Crea una nueva base de datos llamada `twitter_db`.
    
- **Palabras Clave**:
    
    - `CREATE DATABASE`: Instrucción para generar nueva BD.
    - `twitter_db`: Nombre asignado (siguiendo convención `[nombre]_db`).
        

---

## 2. Verificación de Bases de Datos (`SHOW DATABASES`)

- **Propósito**: Lista todas las bases de datos en el servidor MySQL.
- **Uso típico**: Confirmar que `twitter_db` fue creada exitosamente.

---

## 3. Selección de Base de Datos (`USE`)

- **Función**: Establece `twitter_db` como BD activa para operaciones posteriores.
- **Importancia**: Todas las tablas creadas después se almacenarán aquí.

---

## 4. Creación de Tabla `user`

Estructura y componentes:

### 4.1. `user_id`

```MySQL
user_id INT NOT NULL AUTO_INCREMENT
```

- **Tipo**: Entero (`INT`).
- **Restricciones**:
    - `NOT NULL`: Campo obligatorio.
    - `AUTO_INCREMENT`: Genera valores únicos automáticos (1, 2, 3...).
- **Función**: Clave primaria implícita (identificador único).

---

### 4.2. `user_handle`

```MySQL
user_handle VARCHAR(50) NOT NULL UNIQUE
```

- **Tipo**: Texto variable hasta 50 caracteres (`VARCHAR(50)`).
- **Restricciones**:
    - `NOT NULL`: Obligatorio.
    - `UNIQUE`: Valor único en toda la tabla (evita duplicados).
- **Ejemplo**: `@juan_perez`.

---

### 4.3. `email_address`

```MySQL
email_address VARCHAR(50) NOT NULL UNIQUE
```

- **Mismo tipo y restricciones que `user_handle`**:
    - Garantiza que cada email sea único y obligatorio.

### 4.4. Nombre del Usuario

```MySQL
first_name VARCHAR(100) NOT NULL,
last_name VARCHAR(100) NOT NULL
```

- **Estructura**:
    - `first_name`: Primer nombre (100 caracteres máx).
    - `last_name`: Apellido (100 caracteres máx).
- **Restricción**: Ambos campos obligatorios (`NOT NULL`).

### 4.5. `phonenumber`

```MySQL
phonenumber CHAR(10) UNIQUE
```

- **Tipo**: Cadena de **10 caracteres exactos** (`CHAR(10)`).
    - Mejor que `VARCHAR` para datos de longitud fija.
- **Restricción**:
    - `UNIQUE`: Números telefónicos únicos (pero opcional, no tiene `NOT NULL`).

---
### 4.6. `created_at`

```MySQL
created_at TIMESTAMP NOT NULL DEFAULT (NOW())
```

- **Tipo**: Fecha y hora (`TIMESTAMP`).
- **Restricciones**:
    - `NOT NULL`: Siempre tendrá valor.
    - `DEFAULT (NOW())`: Fecha/hora automática al crear registro.
- **Función**: Auditoría de creación de usuarios.


## 🔑 Declaración Explícita de Clave Primaria

```MySQL
PRIMARY KEY(user_id)  
```

**Explicación detallada**:

1. **Qué hace**:
    - Establece formalmente `user_id` como **clave primaria** de la tabla.
    - Garantiza que cada valor en `user_id` sea único y no nulo.
2. **Por qué es importante**:
    - **Identificación única**: Permite buscar/actualizar/eliminar registros de manera inequívoca.
    - **Integridad referencial**: Esencial para relaciones con otras tablas (ej: tweets → usuarios).
    - **Optimización**: MySQL crea automáticamente un índice clustered en la PK, acelerando consultas.
3. **Relación con `AUTO_INCREMENT`**:
    - La combinación `AUTO_INCREMENT + PRIMARY KEY` es el estándar para claves sustitutivas (_surrogate keys_).
    - Genera valores secuenciales únicos automáticamente: 1, 2, 3...

---

## Notas Técnicas

1. **`VARCHAR vs CHAR`**:
    - Usar `CHAR` cuando la longitud es fija (ej: números de teléfono).
    - `VARCHAR` ahorra espacio para textos variables.
2. **Clave Primaria**:
    - Aunque no se declara explícitamente `PRIMARY KEY`, `user_id` con `AUTO_INCREMENT` suele ser la PK implícita. **Por lo que no es necesario escribir `user_id INT NOT NULL AUTO_INCREMENT`**
3. **Seguridad**:
    - Los campos `UNIQUE` previenen duplicados críticos (emails repetidos).
