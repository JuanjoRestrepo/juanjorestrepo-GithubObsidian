### **1. Definición de Base de Datos**
---
**Base de Datos (BD)**: Es un conjunto de datos organizados y almacenados de forma sistemática, lo que permite su consulta de manera eficiente.

- **Almacenamiento**: La base de datos guarda los datos de manera estructurada.
- **Consultas**: El acceso a los datos debe seguir un protocolo o un orden específico, no puede realizarse de forma aleatoria.
- **Características clave**: El acceso no puede ser aleatorio, sino que sigue un protocolo o un orden específico, lo que garantiza la consistencia y rapidez en la consulta.

### **2. Ejemplo Comparativo: Archivos Físicos vs. Base de Datos**
---
- **Archivos Físicos en una Comisaría**:
    - Los archivos de casos policiales están organizados en cajas, que a su vez pueden estar ordenadas alfabéticamente.
    - Este orden permite que se pueda seguir un protocolo para acceder a la información de los archivos (como una búsqueda alfabética).
    - **Limitación**: En comisarías con grandes volúmenes de casos, el acceso y consulta de archivos puede volverse un proceso muy lento.
- **Mejora Tecnológica**:
    - Hoy en día, este problema ha sido resuelto en gran parte por el uso de sistemas electrónicos.
    - **Ventaja de los dispositivos electrónicos**: Permiten realizar consultas y acceder a la información de manera muchísimo más rápida debido al poder de procesamiento que poseen.

### **3. Importancia del Acceso en la Gestión de Datos**
---
- **Gestión de Datos en Ciencia de Datos**:
    - El acceso a los datos es uno de los procesos fundamentales dentro de la _Gestión de Datos_, un campo crucial para la _Ciencia de Datos_.
    - La eficiencia con la que se puede consultar y acceder a los datos impacta directamente en la calidad y rapidez del análisis.
- **Consultas ordenadas**:
    - El acceso a los datos debe seguir un protocolo predefinido (como el ejemplo de búsqueda alfabética en los archivos físicos). Este protocolo asegura que el sistema es capaz de encontrar los datos solicitados de forma eficiente.
    - **Base de Datos Electrónica**: Los sistemas modernos permiten que este acceso se realice de manera automática y rápida, eliminando las limitaciones de los sistemas físicos antiguos.

### **4. Los Sistemas Gestores de Bases de Datos (SGBD)**
---
- **Función Principal**: Son los encargados de permitir el acceso y la gestión de los datos almacenados en las bases de datos.
    
    - **Acceso Eficiente**: Facilitan la consulta y el manejo de grandes volúmenes de datos.
    - **Mecanismos de Organización**: Los SGBD proporcionan un conjunto de herramientas y protocolos que organizan, clasifican y permiten consultas eficientes a los datos almacenados.
- **Ejemplos de SGBD**:
    
    - **SQL** (Lenguaje de Consulta Estructurada): Uno de los lenguajes más usados para interactuar con bases de datos.
    - **SGBD Comunes**: MySQL, PostgreSQL, Oracle Database, Microsoft SQL Server, entre otros.

### **5. Pregunta Clave para Científicos de Datos**
---
- **Acceso a los datos**: Como científicos de datos, una de las preguntas más importantes es cómo acceder a los datos almacenados en una base de datos para análisis.
    - **Respuesta**: El acceso a estos datos se realiza a través de los sistemas gestores de bases de datos (SGBD), que nos proporcionan las herramientas y los lenguajes necesarios para interactuar de manera eficiente con la información.

# **1. Definición de Sistema Gestor de Base de Datos (DBMS)**
---
- **Sistema Gestor de Base de Datos (DBMS)**: Es un software especializado para la **gestión de datos** dentro de una base de datos.
    - Proporciona una interfaz que facilita la **organización**, **acceso**, **calidad** e **integridad** de los datos.
    - Facilita a diferentes profesionales, como **Ingenieros de Datos**, **Analistas de Datos**, **Científicos de Datos** e **Ingenieros de Software**, el trabajo con grandes volúmenes de información de manera eficiente y segura.

# **2. Componentes Principales de un DBMS**
---
- Un DBMS consta de varios lenguajes especializados para diferentes funciones:
    
    1. **Lenguaje de Manipulación de Datos (DML)**: Para realizar operaciones sobre los datos, como la actualización, inserción o eliminación.
    2. **Lenguaje de Definición de Datos (DDL)**: Define la estructura de la base de datos, es decir, la creación de tablas, relaciones, índices, entre otros.
    3. **Lenguaje de Consulta de Datos (DQL)**: Se usa para **consultar** y recuperar datos de la base de datos (ejemplo: SQL).
- **Transparencia de los Componentes**: Aunque los usuarios interactúan directamente con el DBMS, los lenguajes (DML, DDL, DQL) operan a diferentes niveles de forma **transparente**. Los usuarios no necesitan preocuparse por cómo funcionan internamente, solo usan las interfaces que les proporciona el DBMS.

# **3. Funciones Principales del DBMS**
---
- Un DBMS permite realizar varias acciones sobre la base de datos y los datos:
    
    - **Almacenamiento**: Guardar los datos en la base de datos.
    - **Consulta**: Recuperar datos de la base de datos de manera eficiente.
    - **Actualización**: Modificar los datos existentes.
    - **Eliminación**: Eliminar datos de la base de datos.
- **Gestión de Usuarios**:
    
    - Un DBMS también proporciona herramientas para gestionar quién puede acceder a la base de datos, asignando **contraseñas**, **roles** y **permisos** a los usuarios. Esto garantiza la seguridad y control del acceso a los datos.

---

# **4. Tipos de Sistemas Gestores de Bases de Datos (DBMS)**
---
- Existen varios tipos de DBMS, y cada uno se adapta a diferentes representaciones de los datos:
    1. **Sistemas Gestores de Bases de Datos Relacionales (RDBMS)**:
        - Organizan los datos en **tablas** con filas y columnas, que están relacionadas entre sí.
        - Utilizan **SQL** como lenguaje principal para consultas.
        - Ejemplos: MySQL, PostgreSQL, Oracle Database.
    2. **Sistemas Gestores de Bases de Datos Orientados a Documentos (NoSQL)**:
        - Los datos se almacenan en **documentos** en lugar de tablas. Estos documentos pueden tener una estructura más flexible (por ejemplo, en formato JSON o BSON).
        - Ejemplos: MongoDB, Couchbase.



# ¿Qué es una Base de Datos Relacional?
---
Una **Base de Datos Relacional** es un tipo de base de datos que almacena la información en **tablas**, las cuales permiten que los datos se relacionen entre sí.

- **Estructura de Tablas**:
    - **Filas**: Cada fila representa un registro o entrada individual, y contiene un conjunto de valores correspondientes a diferentes atributos.
    - **Columnas**: Cada columna representa un atributo específico de los registros. Por ejemplo, si tenemos una tabla de usuarios, las columnas podrían ser "Nombre", "Correo Electrónico", "Fecha de Registro", etc.
- **Identificador Único**: Cada fila tiene un identificador único (clave primaria) que distingue cada registro del resto. Este identificador es crucial para la gestión de relaciones.

### **Diferencia entre una Base de Datos Relacional y una Hoja de Cálculo (como Excel)**
---
- **Similitud Visual**: Tanto las bases de datos relacionales como las hojas de cálculo pueden parecer similares a primera vista, ya que ambas usan filas y columnas para organizar los datos.
- **Diferencias Estructurales**:
    - **Relaciones**: En una base de datos relacional, las tablas pueden estar **relacionadas** entre sí mediante claves primarias y foráneas. Esto garantiza la integridad y coherencia de los datos.
    - **Consistencia**: Las bases de datos relacionales imponen una mayor consistencia gracias a la implementación de protocolos estrictos para el acceso y modificación de los datos.
    - **Limitaciones de Excel**: Aunque en Excel se pueden crear múltiples tablas y simular relaciones, no hay un protocolo definido que gestione esas relaciones. No es eficiente ni escalable para manejar grandes volúmenes de datos o realizar consultas avanzadas.


### **Elementos Clave en una Base de Datos Relacional**
---
- **Llave Primaria (Primary Key)**: Un campo (o combinación de campos) que **identifica de manera única** a cada registro dentro de una tabla.
    
    - Ejemplo: En una tabla de usuarios, el "ID de Usuario" sería la llave primaria.
- **Llave Foránea (Foreign Key)**: Un campo en una tabla que es la **clave primaria** en otra tabla, creando una relación entre las dos tablas.
    
    - Ejemplo: En una tabla de pedidos, podría haber un campo "ID de Usuario" que se refiere al "ID de Usuario" en la tabla de usuarios, estableciendo una relación entre ambas tablas.
- **JOINS**: Permiten combinar datos de dos o más tablas basándose en relaciones entre los campos. Es una de las herramientas más poderosas para realizar consultas complejas en bases de datos relacionales.
    
    - Ejemplo: Un JOIN puede combinar la tabla de "usuarios" con la tabla de "pedidos" para obtener los pedidos realizados por cada usuario.
- **Funciones Agregadas**: Operaciones que permiten realizar cálculos como contar, sumar o promediar los datos de una tabla o combinación de tablas.
    
    - Ejemplo: `COUNT()`, `SUM()`, `AVG()`, `MIN()`, `MAX()`.

### **Ventajas de las Bases de Datos Relacionales**
---
- **Consultas Avanzadas con SQL**: Gracias al uso de **SQL** (Structured Query Language), se pueden realizar consultas avanzadas y eficientes. Esto incluye recuperar datos específicos, filtrar, agrupar, ordenar y combinar datos de diferentes tablas.
- **Relaciones entre Tablas**: Permiten organizar y manejar datos de forma coherente a través de las relaciones entre tablas. Esto asegura que los datos estén bien estructurados y sean fáciles de mantener.
- **Escalabilidad y Consistencia**: Los datos pueden crecer en volumen, pero la consistencia se mantiene gracias a las relaciones y las restricciones definidas por las claves primarias y foráneas.
