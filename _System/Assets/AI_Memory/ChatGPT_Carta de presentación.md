### **Terraform / IaC**
- Se enfoca en **infraestructura**: servidores, redes, bases de datos, contenedores, buckets, etc.

---

### **Airflow**
- Es un **orquestador de workflows / pipelines de datos**.  
- Su objetivo es **automatizar tareas o flujos de trabajo**, típicamente de procesamiento de datos.  
- Ejemplo: Un pipeline que:
  1. Extrae datos de un S3.
  2. Limpia y transforma esos datos.
  3. Inserta los datos en PostgreSQL.
  4. Genera un reporte en Power BI.

- Airflow **no crea servidores ni redes**, solo ejecuta tareas **sobre la infraestructura existente**.

---

### **Terraform**
- Es una herramienta para **Infrastructure as Code (IaC)**.
- Permite **definir toda tu infraestructura en archivos de código** (HCL – HashiCorp Configuration Language).
- Por ejemplo, puedes crear servidores, redes, bases de datos, buckets de almacenamiento y todo en la nube usando código, en lugar de configurar manualmente en AWS, GCP o Azure.
- Lo importante: **todo queda versionado**, reproducible y fácil de replicar en distintos entornos (dev, staging, prod).

**Ejemplo conceptual en Terraform**:
```hcl
provider "aws" {
  region = "us-east-1"
}

resource "aws_s3_bucket" "my_bucket" {
  bucket = "mi-bucket-de-datos"
  acl    = "private"
}
```
Con esto, Terraform crea un bucket S3 automáticamente, sin tocar la consola web.

---

### **IaC (Infrastructure as Code)**
- Es el concepto general de **tratar la infraestructura como software**.
- Permite:
  - Versionar la infraestructura como código (Git).  
  - Automatizar despliegues (en lugar de manual).  
  - Reproducir entornos idénticos (dev → prod).  
  - Reducir errores humanos y mejorar confiabilidad.  

**Terraform es una implementación de IaC**, hay otras como **CloudFormation (AWS)**, **Pulumi**, **Ansible** (más híbrido de configuración).

---

🔹 **Resumen práctico:**  
Terraform/IaC = Escribes tu infraestructura en código → la despliegas automáticamente → puedes replicarla y versionarla → más confiable, escalable y reproducible.
