Las pruebas unitarias también son una excelente forma de evaluar un Pipeline


## Unit tests - Pruebas Unitarias

- Son códigos que ayudan a probar la funcionalidad de otros codigos
- Se usan comúnmente en flujos de trabajo en Ing de Software
- Asegurar que el código (componentes de un Pipeline de datos) funcione como se espera
- Ayudan a validar datos producidos por un Pipeline
- Los Unit Tests se ejecutan primero antes de que la validación End-To-End termine

## Pytest para Unit Testing

from pipeline import extract, transform, load

	clean_stock_data = transform(raw_stock_data)

## assert and isinstance

```python
pipeline_type = "ETL"
isinstance(pipeline_type, str)
```

- Toma dos argumentos: **un objeto y un tipo de datos**
	- Si el objeto hace match con el tipo de datos, se devuelve *True*

```python
# Assert that the pipeline does indeed take value "ETL"
assert pipeline_type == "ETL"
```

- `assert isinstance`: se usa para afirmar que el objeto `clean_stock_data` toma el tipo *pd.DataFrame*
	- Devuelve *True* si hacen match
	- Si es *False*, se genera un `AssertionError`


## Pytest fixture

- Permiten compartir datos y objetos de prueba entre otras multiples pruebas
- Se usan para **simplificar la configuración de pruebas** y **proporcionar un conjunto de datos de prueba para multiples tests**

![[Pasted image 20250610182236.png]]

- Se crea un fixture para limpiar los datos `clean_data`
- Ese fixture se pasa a la función `test_transformed_data`
- Al ejecutar el test, este podrá acceder al DataFrame limpio creado por el fixture `clean_data`
